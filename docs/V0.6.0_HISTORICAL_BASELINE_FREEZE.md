This document freezes the real released EL Bot v0.6.0 state before the v1.0.0 product-separation program begins.

The purpose is not to declare v0.6.0 perfect. The purpose is to preserve an immutable, truthful reference point for:

- regression comparison;
- migration research;
- legacy Forgey inspection;
- package/install comparison;
- UI/UX comparison;
- benchmark comparison;
- defect reproduction;
- proof that v1.0.0 improves or deliberately changes behavior rather than silently rewriting historical expectations.

Future work must not retroactively redefine what v0.6.0 was.

## 8. Human-test baseline — locked defects / limitations

These defects are part of the frozen v0.6.0 truth. They must not be erased from historical comparison.

### D1 — duplicate multi-word lexical composition

Input:

`credit card`

Observed winner:

`💳 ➡️ 💳`

Expected canonical output:

`💳`

Alternatives showed the duplicate/self-relation candidate scoring above the canonical single-card candidate.

### D2 — correct reverse answer with contradictory failure status

Input:

`🚲`

Observed answer:

`Bicycle.`

Observed UI contradiction:

correct semantic answer and visible `100/100` coexisted with a red failure marker.

### D3 — incomplete mixed-concept translation falsely receiving perfect quality

Input:

`robot zxqvplmno credit card bicycle fox`

Observed released result collapsed essentially to `🚲` while visible quality showed `100/100`.

Known source concepts were silently lost and unresolved evidence was not faithfully represented in the final result.

### D4 — duplicate request lifecycle / repeated Enter

Repeated Enter presses could restart or resubmit inference while processing and could retrigger immediately after completion.

### D5 — long-input semantic explosion

Long repetitive prose completed without crashing but produced very large, repetitive EL output with poor semantic density and many unresolved units.

### D6 — image/provider routing failure

A screenshot/image could be loaded and previewed, but the user-visible terminal result became effectively:

`❌ 📸 -> 🦙 OFF`

This occurred despite the Phase-6 architecture/release having native Forgey vision evidence, demonstrating a runtime routing/observability defect.

### D7 — Ollama/Qwen unavailable in the tested installed environment

The built-in `🦙🔍` probe returned:

`❌🦙📡`

Therefore the installed EL Bot could not reach local Ollama during that human test session, and an unresolved input such as `hopping` could not obtain the intended optional provider/teacher assist.

### D8 — provider/fallback identity ambiguity

The v0.6.0 architecture made it too difficult for the user to distinguish:

- actual Forgey model inference;
- deterministic fallback output;
- optional Qwen/Ollama assist;
- provider-unavailable behavior;
- validation/rejection behavior.

This ambiguity is a primary reason v1.0.0 requires a separately released Forgey product with explicit runtime identity evidence.

### D9 — user-facing training product-boundary mismatch

The hidden EL Bot Admin Console exposed Training Center concepts even though ordinary users must not train Forgey under the v1.0.0 product model.

The v0.6.0 console is therefore historical evidence and a developer-reference UI, not the future user product boundary.

## 10. Migration rules into v1.0.0

When using v0.6.0 as migration input:

### Allowed

- inspect source at the frozen commit;
- compare behavior against the human-test ledger;
- reuse concepts after explicit inspection;
- migrate code/components with recorded provenance;
- reuse test cases as regression cases;
- use old G1/G2 metrics as legacy comparison numbers;
- use package/install behavior as a UX baseline.

### Forbidden

- modifying the historical v0.6.0 release and pretending the modified result was the original;
- relabeling embedded legacy G2 as canonical Forgey G1;
- claiming a known v0.6.0 defect did not exist because v1.0.0 later fixes it;
- using deterministic fallback success as proof of Forgey AI inference;
- using old generation names as a hard-coded requirement in the new Forgey repository;
- allowing the new model runtime ABI to depend on EL Bot's old internal training-directory layout.
